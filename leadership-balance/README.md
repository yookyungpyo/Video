# 리더는 그 중간 어디쯤 — leadership-balance

3×3 수묵화 스토리보드 한 장으로 만든 인스타그램 릴스입니다.
"리더는 조직 중심이어야 할까, 사람 중심이어야 할까"라는 질문에서 시작해, 정답 대신 **조직과 사람 사이에서 매번 다시 균형을 찾아가는 과정**으로 끝납니다. 마지막 장면에서 리더는 멈추지 않고 다리 위를 계속 걸어갑니다.

- React + TypeScript + Remotion 4 · 1080×1920 · 30fps · H.264(yuv420p, BT.709) + AAC · MP4 faststart
- **결과 파일:** `output/leadership-balance.mp4`
- **길이:** **58.33초(1750프레임)**. 목표 타임라인은 52초였고, 실제 내레이션 길이에 맞춰 장면을 늘렸습니다(허용 범위 50~60초 안).
- 내레이션 · 자막 · 배경음악 · 효과음이 모두 들어간 완성본입니다.

## 실행 · 렌더링 명령어 (Windows · VS Code 터미널, `leadership-balance` 폴더에서)

```bash
npm install                # 처음 한 번
npm run preview            # Remotion Studio 미리보기 (컴포지션: LeadershipBalance)
npm run render             # → output/leadership-balance.mp4
npm run verify             # 해상도 · fps · 프레임 수 · 코덱 · yuv420p · faststart 검사 + output/stills/scene-0X.png
```

`npm run render`는 영상을 무음으로 렌더링한 뒤 `public/audio/track.mp4`를 그대로 합치고 faststart를 적용합니다(`scripts/render.mjs`).

이미지 · 음성 · 문구를 바꿀 때 쓰는 명령입니다.

```bash
npm run split                              # assets/leadership-storyboard.png → assets/scenes/scene-01~09.png (Node + sharp)
pip install numpy pillow opencv-python     # 처음 한 번 (아래 Python 스크립트용)
npm run textures                           # 원본에서 종이 결 · 먹 가장자리 생성 → public/textures/
npm run take                               # assets/narration/full-take.mp3 → 장면별 scene-0X.wav
npm run audio                              # 장면 길이 · 발화 타이밍 · 음악 · 효과음 · 믹스 → timing.json, track.mp4
npm run timeline                           # 자막 타임라인 → caption-timeline.json
```

## 이미지 처리

- **분할:** `scripts/split-storyboard.mjs`가 스토리보드의 구분선을 픽셀에서 찾아 3×3으로 자르고, 칸 테두리 선이 남지 않게 안쪽에서 잘랐습니다. 왼쪽 위 → 오른쪽 아래 순서, 한 칸은 약 384×421px입니다.
- **변경 없음:** 인물의 얼굴 · 안경 · 헤어스타일 · 의상, 수묵 질감과 먹선은 원본 그대로입니다. 다시 그리거나 생성한 부분이 없습니다.
- **9:16 배치:** 거의 정사각형인 원본을 늘리지도, 세로 화면에 맞춰 잘라 채우지도 않았습니다. 화면 폭 1080px에 **장면 전체**를 놓고(y 383–1563), 위아래는 검은 먹으로 확장했습니다. 경계는 직선이 아니라 먹이 번진 듯한 불규칙한 가장자리입니다. 인스타그램 UI가 가리는 위 350px · 아래 330px에는 그림도 글자도 없습니다.
- **확대율:** 원본 대비 약 2.8배, 가장 당겼을 때(01 · 09, 스케일 1.28 · 1.30) 약 3.6배입니다. 원본 한 칸이 384px이라 큰 화면에서는 선이 다소 부드럽게 보입니다. 고해상도 원본이 있으면 `assets/scenes-hires/scene-0X.png`로 넣고 `npm run split` → `npm run render`.
- **텍스트:** 이미지에 합성하지 않았습니다. 모든 글자는 Remotion의 별도 레이어입니다.
- **2.5D:** 인물을 오려내지 않았습니다. 02 · 04 · 08은 가까운 영역(인물 / 앞쪽 구성원 / 난간)을 가장자리가 부드러운 레이어로 겹쳐 2~3% 더 크게 움직이는 약한 패럴랙스입니다.

## 장면별 모션 (`src/config/motion.ts`)

장면 시간은 실제 음성에 맞춘 값입니다. 장면마다 다른 움직임을 썼고, 같은 줌을 반복하지 않았습니다.

| # | 시간(초) | 카메라 | 들어오는 전환 |
|---|---|---|---|
| 01 후킹 | 0.0–4.6 | Push In: 전체 구도 → 주인공 클로즈업(1.00→1.28), Ease Out, 첫 프레임부터 이동 | 검은 화면에서 페이드인 |
| 02 현실 | 4.6–9.3 | Low-angle 느낌의 Push In(1.10→1.26): 건물 쪽에서 시작해 위로 올라가며 인물로 이동 | 먹 번짐 |
| 03 갈등 | 9.3–13.8 | 느린 Pan: 리더 → 구성원, 미세한 Push In(1.14→1.20) | 종이 질감 디졸브 |
| 04 반대편 | 13.8–20.2 | 느린 Pull Out(1.20→1.00): 리더에서 구성원 전체로, 앞쪽 인물에 약한 패럴랙스 | 붓 터치 와이프 |
| 05 고민 | 20.2–27.2 | Crane Up 모사: 리더 얼굴(1.30) → 저울 전체(1.00), 이후 약 1.7초 정지 | 먹 번짐 |
| 06 깨달음 | 27.2–31.6 | 느린 Tilt Up + 저울이 더 기우는 듯한 2D 회전(+1.2°→−2.2°). 3D Orbit 없음 | 저울 연결: 05의 화면이 저울대처럼 기울며 06의 기운 저울로 이어짐 |
| 07 통찰 | 31.6–38.9 | 좌우 Tracking 모사 Pan: 조직(왼쪽) 쪽으로 이동 → 멈춤 → 사람(오른쪽) 쪽으로 전환 | 종이 질감 디졸브 |
| 08 철학 | 38.9–45.9 | 느린 Push In(1.00→1.12): 손과 다리 난간 쪽으로, 난간에 약한 패럴랙스 | 먹 번짐 |
| 09 결론 | 45.9–58.3 | 느린 Pull Out(1.30→1.00): 인물은 작아지고 풍경이 넓어짐. 마지막 말 뒤 약 1.5초 정지 후 페이드아웃 | 다리 연결: 08의 난간 목재로 밀고 들어가 09의 다리 목재에서 빠져나옴 |

- 전환 길이는 0.4~0.6초입니다.
- **05 → 06:** 두 그림의 저울 모양이 달라 픽셀 단위로 일치하는 매치 컷은 아닙니다. 같은 방향의 회전으로 움직임을 이어 붙였습니다.
- **08 → 09:** 마찬가지로 목재 질감과 밀고 들어가는 움직임을 이어 붙인 것이고, 구조물이 정확히 겹치지는 않습니다.
- 전환 중 완전히 검은 프레임은 없습니다(시작과 끝의 페이드만 검정).

## 타이포그래피 (`src/components/Captions.tsx` · `src/data/captions.json`)

- **폰트:** 일반 문장은 Noto Serif KR(명조), 핵심 단어는 Pretendard ExtraBold. 색은 아이보리와 화이트뿐이고, 강조는 크기와 굵기로 합니다.
- **움직임:** 줄마다 실제로 말하는 순간에 순서대로 등장합니다. 아래에서 20px 올라오며 0.4초 페이드인 → 완전히 정지 → 0.3초 페이드아웃. 흔들리거나 계속 움직이는 효과는 없습니다.
- **행간:** 줄 높이를 글자 크기에서 계산해(명조 1.36배, 고딕 1.2배) 크기가 다른 줄끼리 겹치지 않습니다. 줄 자리는 처음부터 고정이라 뒤 줄이 나올 때 앞 줄이 밀리지 않습니다.
- **배경:** 글자 아래에만 검은 그라데이션을 깔았습니다. 테두리와 강한 그림자는 없습니다.
- **배치:**

| # | 화면 자막 | 위치 |
|---|---|---|
| 01 | 리더는 / **조직 중심?** / **사람 중심?** (시간차 등장) | 하단 왼쪽 (마이크와 손을 피함) |
| 02 | 조직의 성과를 생각하면 / **냉정한 결정**을 / 내려야 한다. | 하단 왼쪽 |
| 03 | 하지만 그 결정이 / **누군가에게는 상처**가 / 될 수도 있다. | 하단 왼쪽 (어깨 위의 손 아래) |
| 04 | 사람만 생각하다 보면 / **원칙과 목표**가 / 흔들릴 수도 있다. | 하단 중앙 |
| 05 | 어디까지 **이해**하고 · 어디서부터 **원칙**을 지킬까 | 중하단 좌 · 우 (양쪽 저울 접시 아래, 어깨 위) |
| 06 | 어쩌면 리더십에는 / **정해진 중심은 없다** | 상단 중앙 |
| 07 | 때로는 **단호하게** → 때로는 **한 걸음 물러서서** | 하단 왼쪽(조직 쪽) → 하단 오른쪽(사람 쪽), 카메라 방향과 함께 교체 |
| 08 | 중요한 건 → 어느 한쪽을 선택하는 게 아니라 / **무엇이 더 중요한지** / **판단하는 일** | 하단 중앙 (손 아래) |
| 09 | **리더는 그 중간 어디쯤** → 그 균형에는 정답이 없기에 / **늘 어렵다.** | 하단 중앙. 마지막 문장은 약 5초 유지 |

- 상단 배치는 06 한 곳입니다. 다른 장면은 그림 위쪽에 얼굴이 있어서, 얼굴 · 손 · 핵심 오브젝트를 가리지 않는 아래쪽이나 어깨 위에 두고 좌 · 중앙 · 우로 변화를 줬습니다.
- 위 350px · 아래 330px · 오른쪽 150px(인스타그램 UI 영역)에는 글자가 없습니다.

## 내레이션

- **목소리:** ElevenLabs `eleven_v4` · **Minho - Deep & Trustworthy Narrator** (차분하고 낮은 한국어 남성).
- **녹음:** 원고 전체를 한 번에 읽은 테이크(54.9초, `assets/narration/full-take.mp3` = `take-a.mp3`)를 문단 사이 쉼에서 장면별로 나눴습니다. **음성 속도를 바꾸거나 자르지 않았습니다.** 원고는 지시서의 문장 그대로이고, 호흡을 위해 쉼표만 몇 개 넣었습니다.
- **다른 테이크:** `assets/narration/take-b.mp3`(54.6초). `full-take.mp3`로 복사한 뒤 `npm run take` → `npm run audio` → `npm run timeline` → `npm run render`.
- **직접 녹음으로 교체:** `assets/narration/scene-01.wav` … `scene-09.wav`(mp3 · m4a 가능)를 넣고 `npm run audio`부터 실행합니다.
- **싱크:** 구절이 시작되는 시각을 음성의 쉼에서 찾아 자막을 맞췄습니다. 쉼 없이 이어 말한 구절(예: "리더는 / 조직 중심이어야…")은 음절 수 비율로 추정한 시각입니다.

## 음악 · 효과음

- 사용 허가가 확인된 음원 파일이 없어서 스크립트가 **직접 합성한 원곡과 효과음**을 넣었습니다(샘플 · 외부 음원 없음). 실제 악기 녹음이 아니라 합성음입니다.
- **BGM:** 54BPM, A단조. 낮은 피아노 한 음과 첼로 음역의 긴 현. 05–06(저울)에서 얇아지고, 07–08에서 느린 선율이 생기며, 마지막은 해결되지 않는 서스펜디드 화음으로 끝납니다. 목소리가 나오는 동안 자동으로 낮아집니다.
- **효과음:** 붓 스침(시작, 먹 번짐 전환, 04의 붓 와이프), 종이 스침(디졸브), 저울의 삐걱임과 사슬 소리(05 → 06), 목재 소리(08 → 09), 약한 바람(07 · 09).
- **교체:** `assets/music/music.mp3`(또는 wav, m4a)를 넣고 `npm run audio`. `src/data/script.json`의 `"music"`을 `"none"`으로 바꾸면 음악 없이 렌더링됩니다.

## 길이

- 내레이션에서 문단 사이 쉼을 뺀 실제 발화가 49.6초입니다. 장면마다 앞 0.28초 · 뒤 0.45초의 숨, 05의 정적, 마지막 말 뒤 2.4초를 더해 **58.33초**입니다.
- 지시서의 목표 시간보다 길어진 장면: 04(+0.4초) · 05(+1.0) · 07(+1.3) · 08(+1.0) · 09(+4.4). 01–03 · 06은 목표보다 조금 짧습니다. 장면별 계산은 `output/timing-report.txt`.

## 검수

`npm run verify`와 MP4에서 뽑은 프레임으로 확인한 항목입니다.

- 1080×1920 · 30fps · 1750프레임 · H.264 · yuv420p · AAC 48kHz 스테레오 · faststart
- 9장면 순서, 인물 외형(원본 그대로), 자막 잘림 · 겹침, 전환 구간의 검은 프레임
- 재생 속도: 프레임 수 ÷ 30 = 영상 길이 = 오디오 길이

직접 확인이 필요한 항목입니다.

- **아이폰 사진 앱 저장:** 호환되는 형식으로 인코딩했지만, 실제 저장 성공 여부는 기기에서 확인해야 합니다.
- **소리:** 음량과 타이밍은 수치로 확인했고, 목소리 톤 · 음악과의 균형은 들어 보고 판단해야 합니다.
