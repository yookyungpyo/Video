HyperFrames와 Remotion은 무엇이 다른가

둘 다 웹 화면(HTML)을 한 프레임씩 찍어 영상으로 만듭니다. 결과물은 거의 같았습니다. 차이는 움직임을 어떻게 적느냐에 있습니다.

한 줄로 말하면

HyperFrames
큐시트 방식

무대(HTML)에 소품을 먼저 배치하고, “2.75초에 카드를 위에서 떨어뜨려라” 같은 지시를 타임라인에 적습니다. 애니메이션은 GSAP가 맡습니다.

tl.from("#p1", { y: -760, duration: 0.5,
         ease: "bounce.out" }, 2.75);
Remotion
프레임 함수 방식

React 컴포넌트가 “지금 몇 번째 프레임인가”를 받아서, 그 순간 카드의 위치를 직접 계산합니다. 매 프레임 그림을 새로 그립니다.

const y = interpolate(frame, [83, 98],
  [-760, 0], { easing: Easing.bounce });

만들면서 겪은 일

HyperFrames
  • 내장 검사가 숫자 “23”의 글자 대비 부족, 저장 버튼 문구 줄바꿈, 비어 있는 첫 화면을 잡아줬습니다.
  • GSAP를 인터넷(CDN)에서 불러오는 기본 방식이 이 환경에서 막혀, 파일을 프로젝트에 직접 넣었습니다.
  • 반복문 안의 타이밍을 겹침으로 잘못 읽은 경고가 몇 개 있었습니다.
Remotion
  • 기존 클레이 템플릿과 공용 세이프존 상수를 그대로 가져다 썼습니다.
  • 튕김·스프링·출렁임을 모두 프레임 계산식으로 적어 코드가 더 길어졌습니다.
  • 렌더는 더 빨랐고, 세이프존은 저장소 스크립트로 직접 검사했습니다.

언제 무엇을 쓸까

Remotion

시리즈로 계속 찍는 영상

카드뉴스, 마스코트 릴스처럼 틀은 같고 문구만 바뀌는 영상. 템플릿과 세이프존 설정이 이미 갖춰져 있습니다.

HyperFrames
